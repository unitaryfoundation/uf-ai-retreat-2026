# Instructions for agents

This repo is the shared record of the UF Fall Retreat 2026 (AI in Quantum Information Processing, November 13–15, 2026). Many people and agents write to it at once, and it becomes a public archive afterwards. Read [`README.md`](README.md) for the overview.

## Hard rules

- **Never commit** email addresses, phone numbers, wifi or door codes, credentials, or API keys. If source material contains them, leave them out.
- **Never edit `INDEX.md` files.** They are generated by `scripts/build_index.py` from entry front matter.
- **One entry per file.** Add a new file; do not append to a shared list.
- **Do not rewrite other people's entries.** Add to a "Notes" section, or create your own entry and link to theirs. Fixing typos and broken links is fine.
- **Attribute.** Every entry names the human it came from. Do not invent content or attribute a claim to someone who did not make it; if you are transcribing or summarising, say so in the entry.
- **No force pushes, no history rewrites.**

## Conventions

- File and folder names: `lowercase-kebab-case`. People are `<first-last>`, matching the file name in `attendees/`.
- Front matter: flat `key: value` lines between `---` fences at the top of the file. Quote strings with double quotes. No nested YAML, no lists; use a comma-separated string for several names.
- `status` on problems and structures is one of `idea`, `pitched`, `group-formed`, `done`, `parked`.
- When a group forms around a chart entry, set the entry's `status: group-formed` and `group: "<group-slug>"`, and link back from the group's `README.md`.
- Use relative links between files so they work on GitHub and in a local clone.
- Keep large binaries out. Photos of the wall charts go in `inbox/` or the relevant session folder, resized to under about 2 MB.

## Commit routine

```bash
git pull --rebase
python3 scripts/validate.py
git add <the files you changed>
git commit -m "<folder>: <what you added>"
git pull --rebase && git push
```

Make small commits that touch only your own files. If a push is rejected, pull with rebase and push again. If a rebase conflicts on an `INDEX.md`, take the remote version; it will be regenerated.

## Answering questions from the repo

- Start from the `INDEX.md` in the relevant folder, then open the entries.
- `attendees/` tells you who is here, their workflow and what they want to learn.
- `charts/` is the current inventory of problems, tools and structures; `groups/` is what people decided to work on.
- `program/schedule.md` tells you what is happening when.
- Say when the repo does not contain the answer; do not fill gaps from guesswork.
